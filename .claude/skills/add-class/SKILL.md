# 클래스·하위 클래스 추가

요청: $ARGUMENTS

## 먼저 읽을 것

- 룰북 6단계(공통 변환 규칙, 기존 클래스 4개 표, 결정 기록: 능력치 자유 배분, 무기 마스터리 원문대로), 2단계(판정 분류), 3단계(행동 경제·반응), 7단계(짧은·긴 휴식 회복), 8단계(훅 목록).
- 원문: `docs/srd/03_Classes/<class>.md`. 레벨 상한은 12.

## 순서

1. 원문에서 기본 특성(HP 주사위, 내성, 기능, 무기·갑옷 훈련)과 1~목표 레벨 기능을 표로 뽑는다.
2. 기능마다 룰북 6단계 형식으로 변환안을 만든다: 원문 요지 / 내 게임 안 / 구분([원문 유지]·[변형]·[자체]) / 이유.
   - 거리·시간은 공통 변환, 반응형 기능은 반응 설정 대상, 도구 숙련·언어는 삭제, HP는 고정값.
   - 서술형 기능은 1차 제외하거나 대화 분기·감지·소환·표면 같은 기존 시스템으로 바꾼다.
   - SRD에 없는 하위 클래스는 새 이름·새 설명으로 자체 설계(`"source": "original"`). BG3 하위 클래스 이름은 쓰지 않는다.
3. 변환표를 사용자에게 보여 주고 확인받는다. [변형]·[자체] 항목은 꼭 짚는다.
4. `data/classes/<id>.json` 작성: `hit_die`, `saves`, `skills{choose, from}`, `training`, `weapon_mastery`, `spellcasting`(능력치·슬롯표·준비 수·목록), `resources`(이름·횟수·회복: short/long), `features[]`(level, hook, condition, effects, resource, script), `subclasses[]`.
5. 스크립트가 필요한 기능은 효과 스크립트와 테스트를 만든다. 레벨 1→목표 레벨 성장 테스트(자원 수, 슬롯, 기능 목록)를 넣는다.
6. 클래스 주문 목록이 새로 필요하면 `/add-spell`로 넘긴다.
7. 동료로 쓸 수 있게 시작 장비 꾸러미와 `sprite_parts`를 정한다.
8. `docs/rules/changes.md`에 추가 내용을 적고 `/verify`.

## 보고

기능 변환표, 새 자원·스크립트, 사용자 결정이 필요한 항목.
